# CNCSS — Симулятор ЧПУ-обработки (3D)

## Описание проекта
CNCSS — это приложение на базе WPF и Helix Toolkit, предназначенное для визуализации траекторий G-кода и симуляции процесса удаления материала с использованием воксельной модели заготовки.

## Основные возможности
- **Парсинг G-кода**: Чтение и интерпретация стандартных команд (G0, G1, G2, G3, M-коды).
- **3D Визуализация**: Отображение траектории движения инструмента в реальном времени.
- **Симуляция заготовки**: Воксельная модель (VoxelStock), которая динамически изменяется при проходе инструмента.
- **Управление**: Пуск, пауза, остановка и регулировка скорости симуляции.
- **Информационная панель**: Вывод текущих координат, подачи (Feed), оборотов (Spindle) и состояния системы.

## Структура проекта

### 1. Logic (Логика)
- `GCodeParser.cs`: Разбирает текстовый файл G-кода в список объектов `ParsedCommand`.
- `CommandReplayer.cs`: Управляет воспроизведением команд, вычисляет промежуточные точки для анимации.
- `ArcCalculator.cs`: Отвечает за расчет геометрии дуг (G2/G3).

### 2. Data (Данные)
- `MachineState.cs`: Хранит текущее состояние станка (позиция, подача, активный инструмент, модальные группы).
- `ParsedCommand.cs`: Объектное представление одной строки G-кода.
- `Tools/`: Набор классов для различных типов инструментов (EndMill, Drill, FaceMill), реализующих интерфейс `ITool`.
- `VoxelChunk.cs`: Оптимизированная структура для хранения данных воксельной модели.

### 3. Vis (Визуализация)
- `ToolpathBuilder.cs`: Генерирует 3D-сетку (Mesh) для отображения траектории.
- `VoxelStock.cs`: Управляет отображением и обновлением заготовки. Использует воксельную сетку для симуляции вырезания материала.

### 4. UI (Интерфейс)
- `MainWindow.xaml`: Главное окно с HelixViewport3D и панелями управления.
- `ViewModels/`: Реализация паттерна MVVM для связи логики с интерфейсом.

## Принцип работы
1. **Загрузка**: Пользователь открывает файл G-кода.
2. **Парсинг**: Система анализирует код, строит полную траекторию и определяет границы обработки.
3. **Инициализация**: Создается воксельная модель заготовки заданных размеров.
4. **Симуляция**: 
   - `CommandReplayer` пошагово выполняет команды.
   - Кадр за кадром обновляется позиция инструмента в `MachineState`.
   - Если инструмент находится в теле заготовки, `VoxelStock` удаляет соответствующие воксели.
   - Интерфейс обновляет текстовые данные и 3D-сцену.

## Технологический стек
- **Язык**: C# (.NET)
- **UI**: WPF
- **3D Движок**: Helix Toolkit (WPF)
- **Архитектура**: MVVM

## Воксельная модель и оптимизация
Симуляция удаления материала реализована на базе воксельной сетки с глубокой оптимизацией:

### 1. Структура данных (Чанки)
- **Чанки (Chunks)**: Заготовка разбита на блоки 32x32x32 вокселя.
- **Битовое хранение**: Состояние вокселя хранится как 1 бит в массиве `ulong`. Это в 8-32 раза экономит память по сравнению с `byte` или `bool`.
- **Флаги состояния**: Чанки имеют флаги `IsEmpty` и `IsFull`, что позволяет мгновенно пропускать пустые области при расчетах.

### 2. Оптимизация вычислений (Cutting)
- **Параллелизм**: Использование `Parallel.For` для одновременной обработки нескольких чанков на всех ядрах CPU.
- **Bounding Box**: Расчет удаления материала производится только в области (AABB), которую пересекает траектория инструмента.

### 3. Оптимизация визуализации (Greedy Meshing)
- **Greedy Meshing**: Алгоритм объединяет соседние грани вокселей в один большой полигон, радикально снижая количество треугольников для отрисовки.
- **Culling**: Отрисовываются только внешние грани, граничащие с пустотой. Внутренние грани игнорируются.
- **Асинхронность**: Генерация 3D-сетки вынесена в фоновые задачи (`Task.Run`), что исключает фризы интерфейса.
- **Dirty Flags**: Перерисовываются только те чанки, в которых реально изменился материал.

## Парсинг и обработка G-кода
Логика интерпретации G-кода построена на событийном разборе с сохранением состояния:

### 1. Реестр кодов (GCodeRegistry)
- **Шаблоны (GCodeTemplate)**: Каждая команда (G0, G1, M3...) описана с учетом её **модальности**.
- **Модальность**: Разделение на модальные (действуют до отмены, например G1) и немодальные (действуют одну строку, например G4) команды.
- **Параметры**: Стандартизированные адреса (X, Y, Z, F, S, I, J, K) для исключения ошибок разбора.

### 2. Парсер (GCodeParser)
- **Регулярные выражения**: Быстрый поиск паттернов `Буква+Число` и извлечение комментариев.
- **MachineState**: Парсер эмулирует работу ЧПУ-контроллера, отслеживая текущие координаты, подачу, активный инструмент и режимы (G90/G91).
- **ParsedCommand**: Каждая строка кода превращается в объект, содержащий слепки состояния станка "до" и "после" выполнения команды. Это позволяет мгновенно переходить к любой строке программы с корректным отображением параметров.

## Состояние станка (MachineState)
Класс `MachineState` является "цифровым двойником" контроллера ЧПУ и хранит все параметры системы в любой момент времени:

### 1. Геометрия и позиционирование
- **Координаты (X, Y, Z, A, B, C)**: Текущее положение инструмента.
- **Предыдущие координаты**: Используются для расчета векторов движения и объема удаляемого материала.
- **Режимы позиционирования**: Поддержка абсолютных (`G90`) и относительных (`G91`) координат.
- **Системы координат**: Активная рабочая система (`G54-G59`).
- **Плоскости**: Выбор плоскости интерполяции (`G17` XY, `G18` XZ, `G19` YZ).

### 2. Технологические параметры
- **Подача (Feedrate)**: Разделение на запрограммированную (`F`) и эффективную (с учетом `G0` или рабочих ходов).
- **Шпиндель**: Скорость вращения (`S`), состояние (вкл/выкл) и направление (`M3/M4`).
- **Инструмент**: Номер активного инструмента (`T`), корректоры на длину (`H`) и радиус (`D`).
- **Охлаждение (СОЖ)**: Состояние системы полива.

### 3. Управление состоянием
- **Модальные группы**: Хранение активных режимов движения (`G0, G1, G2, G3`) и коррекций.
- **Метод Clone()**: Позволяет создавать независимые копии состояния для каждой команды G-кода, что критично для корректной работы визуализации при перемотке программы.
- **Reset()**: Сброс всех параметров к значениям по умолчанию (Home position).

## Взаимодействие логики и визуализации
Проект CNCSS использует четкое разделение между расчетами (Logic) и отображением (Vis), связанное через объекты данных (Data).

### 1. Поток данных (Data Flow)
1.  **Парсинг**: `GCodeParser` преобразует текстовый файл в список `ParsedCommand`. Каждая команда содержит "слепок" состояния станка (`MachineState`).
2.  **Траектория**: `ToolpathBuilder` проходит по списку команд и генерирует 3D-линии (Helix Toolkit), используя координаты из `MachineState` каждой команды.
3.  **Симуляция**: `CommandReplayer` позволяет "проигрывать" команды по одной. Он обновляет глобальное состояние станка, которое служит источником данных для UI и воксельной модели.

### 2. Связь с воксельной моделью (Voxel Simulation)
- Когда инструмент перемещается между точками (от `PreviousPosition` к `CurrentPosition`), вызывается метод `VoxelStock.CutCylinder`.
- **Логика**: Вычисляет вектор движения и радиус инструмента.
- **Визуализация**: Если воксели были удалены, чанк помечается как `IsDirty`. В следующем кадре асинхронно пересчитывается 3D-сетка этого чанка.

### 3. Синхронизация с интерфейсом (UI Sync)
- **Интерполяция**: `MainWindow` использует таймер для плавного перемещения инструмента между точками G-кода, вычисляя промежуточные координаты на основе текущей подачи и FPS.
- **Слепки состояния**: Благодаря тому, что каждая `ParsedCommand` хранит `EndState`, выбор любой строки в списке мгновенно синхронизирует 3D-вид, позицию инструмента и текстовые индикаторы.
- **Инструменты**: Параметры из `ToolViewModel` (диаметр, длина) напрямую влияют на визуальную модель фрезы и параметры вырезания в воксельной модели.

### 4. Оптимизация взаимодействия
- **Асинхронность**: Расчеты вокселей и генерация мешей происходят в фоновых потоках (`Task.Run`), чтобы не блокировать отрисовку 3D-сцены (60 FPS).
- **Событийная модель**: Обновление визуализации заготовки происходит только при изменении материала в чанках (`IsDirty`), что экономит ресурсы CPU/GPU.
