Проект: CNCSS -> CNC Machine Simulator (Fanuc 0i-MF Plus style)
Дата: 2026-04-29

Цель
- Превратить текущий WPF-проект в тренажер ЧПУ с кинематической моделью станка.
- Основной интерфейс управления: виртуальная стойка FANUC 0i-MF Plus (экран + рабочие клавиши).
- Взаимодействие с симуляцией должно происходить через стойку, а не через отдельные кнопки UI.
- Ориентир по UX и сценарию работы: прототип уровня Nanjing Swansoft CNC.

Принципы реализации
1) Разделение ответственности:
   - Controller (логика стойки),
   - Machine (кинематика + движение),
   - Simulation (интеграция/события),
   - UI (визуальные компоненты).
2) MainWindow остается хостом компоновки, без бизнес-логики исполнения.
3) Сначала создается минимально рабочая вертикаль:
   кнопка стойки -> команда контроллера -> событие -> движение станка -> обновление 3D.

Архитектурные этапы
Этап 1. Каркас системы (MVP ядро)
- Создать шину событий симуляции (ISimulationBus/SimulationBus).
- Создать интерфейсы IControllerCore и IMachineCore.
- Вынести таймерный цикл симуляции из MainWindow в MachineCore.
- Подключить MainWindow к новой архитектуре как к оркестратору.

Этап 2. Кинематическая модель станка
- Ввести MachineAxesState и AxisState (XYZ на старте).
- Реализовать Vmc3AxisKinematicsModel (базовая 3-осевая кинематика).
- Добавить travel limits, soft limits, home/zero return.
- Поддержать базовые режимы движения: MEM/JOG/ZERO RETURN.

Этап 3. Ядро стойки FANUC
- Реализовать ControllerMode и ControllerStatus.
- Реализовать команды: CycleStart, FeedHold, Reset, ModeChange.
- Событийно связать ControllerCore и MachineCore.
- Добавить базовую модель alarm/diagnostic событий.

Этап 4. Панель FANUC (UI)
- Добавить FanucPanelControl с физическими кнопками.
- Добавить FanucCrtScreenControl с экранными страницами.
- Перенести управление запуском/паузой из старого UI в панель стойки.
- Оставить старые кнопки как временно скрытые/вторичные (до полного перехода).

Этап 5. Исполнение G-code через контроллер
- Ввести ProgramExecutionService.
- Перевести исполнение на канонические блоки движения (MotionBlock).
- Использовать существующий parser как источник блоков на переходном этапе.
- Постепенно отделить синтаксический разбор от интерпретации модальных состояний.

Этап 6. Материал и визуализация
- Сохранить текущий VoxelStock как backend снятия материала.
- Переназначить источник траектории: только от MachineCore.
- Добавить события ProgramLineExecuted и MachineStateChanged для UI.
- Оптимизировать частоту обновления меша и UI по кадру.

Этап 7. Достоверность контроллера и UX
- Добавить ключевые экраны: POS, PROG, OFFSET, SYSTEM, ALARM, DIAGN, SETTING.
- Реализовать softkey-навигацию и обработку клавиш.
- Добавить блокировки/interlock и диагностические сообщения.
- Поддержать single block, optional stop, dry run (по приоритету).

Этап 8. Тесты и валидация
- Unit tests на ControllerCore и MachineCore.
- Golden-тесты сценариев выполнения G-code.
- Сценарные тесты пользовательских действий на виртуальной стойке.
- Проверка регрессий производительности для воксельной симуляции.

Порядок запуска работ (прямо сейчас)
1) Добавить каркас папок и базовые интерфейсы ядра.
2) Добавить in-memory SimulationBus.
3) Добавить минимальный MachineCore с Tick(dt) и состоянием осей.
4) Добавить минимальный ControllerCore с командами запуска/паузы/сброса.
5) Подключить MainWindow к новым сервисам без полного переписывания UI.

Критерий первого инкремента
- Управление циклом (Cycle Start / Feed Hold / Reset) проходит через ControllerCore.
- MachineCore публикует состояние через шину событий.
- MainWindow читает события и обновляет визуализацию без прямого исполнения логики.
- Проект собирается, текущая визуализация траектории остается рабочей.
